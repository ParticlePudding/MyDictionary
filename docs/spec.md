## 1. 概要

| 項目 | 内容 |
|---|---|
| 目的 | 起動してすぐ引ける、個人・小さなチーム向けの辞書 |
| 対象 | Windows 10 / 11(64ビット) |
| 言語 | Rust(edition 2021) |
| GUI | Win32 API を直接使用(`windows` クレート 0.58)。標準コントロール + 一部を自前で描画 |
| 保存 | SQLite(`rusqlite` 0.32、`bundled` で静的リンク) |
| 配布 | 実行ファイル1つ(`MyDictionary.exe`、約1.7MB)。依存は Windows 標準の DLL のみ |
| ライセンス | MIT |
| 版 | 2.02(Cargo のパッケージは `mydictionary` 2.0.2) |

### 設計の方針
- **起動を待たせない**: ウィンドウを先に出し、辞書の読み込みは別スレッドで行う。
- **検索はメモリ上で行う**: 起動時に全件を読み込み、入力のたびにメモリ上を絞り込む。SQL での検索はしない。
- **画面に依存しない部分を分ける**: 検索・保存・取り込みなどは、Windows 以外でもビルドとテストができる。
- **壊れにくさ**: 書き込みは必ず [安全手順](#6-書き込みの安全手順) を通す。
- **通信しない**: アプリ自身は、共有フォルダへのアクセス(辞書・設定・画像のファイルの読み書き)のほかに、ネットワークへ接続しない。URL のリンクは、ブラウザーに開かせるだけ。URL の画像を読み込む、新しい版を調べる、といった機能は入れない。

assets/app.png    アイコンの元画像(512 × 512)

THIRD-PARTY-NOTICES.txt   使用しているオープンソースソフトウェアのライセンス(tools/third_party_notices.py で作る)

  license.rs      ライセンス表示の文面(LICENSE と THIRD-PARTY-NOTICES.txt を埋め込む) ← 画面に依存しない
  ui.rs           色・寸法・フォント、ボタンの描画、入力欄の枠、クリップボード   ← Windows のみ

`ui.rs` `dialogs.rs` `gui.rs` は `#[cfg(windows)]` で、Windows 向けのときだけコンパイルされます。

### 依存クレート
| クレート | 用途 |
|---|---|
| `rusqlite`(`bundled`, `backup`) | SQLite。`backup` は、バックアップ API でのスナップショットに使う |
| `serde_json` | JSON の解析と、文字列のエスケープ |
| `windows`(Windows のみ) | Win32 API |
| `embed-resource`(ビルド時) | マニフェストの埋め込み |

### ライセンス表示
実行ファイルには、依存クレート(と、その依存)のうち実行時にリンクされるもの、Rust の標準ライブラリ、SQLite が含まれる。MIT などのライセンスの条件に従い、それらの著作権表示とライセンスの全文を次の2か所に置く。

- リポジトリ直下の `THIRD-PARTY-NOTICES.txt`(Release にも `LICENSE` と一緒に添付する)
- アプリの「設定」→ 左下の「ライセンス情報」。`src/license.rs` が `LICENSE` と `THIRD-PARTY-NOTICES.txt` を `include_str!` で埋め込み、読み取り専用の欄に表示する

`THIRD-PARTY-NOTICES.txt` は `python tools/third_party_notices.py` で作る。`cargo tree --target x86_64-pc-windows-msvc -e normal,no-proc-macro` で exe に含まれるクレートを調べ、各クレートの MIT ライセンスの文面を、同じ文面ごとにまとめて書き出す(「MIT OR Apache-2.0」のように選べるものは MIT を選ぶ)。ビルド時だけに使うクレート(`embed-resource` など)と手続きマクロは exe に含まれないので載せない。

依存を更新して Cargo.lock が変わったら、スクリプトで作り直す。作り直し忘れは、`license` の自動テスト(載せたクレートの版が Cargo.lock と合うか)で分かる。

## 3. データ

### 3.1 保存場所
| 種類 | 場所 |
|---|---|
| 設定 | 実行ファイルと同じフォルダの `MyDictionary.ini`(あれば)。無ければ `%AppData%\MyDictionary\MyDictionary.ini` |
| 辞書 | 設定で指定したパス。既定は、設定ファイルと同じフォルダの `dictionary.db` |
| しおり | 設定ファイルと同じフォルダの `bookmarks.tsv` |
| バックアップ | `%LocalAppData%\MyDictionary\backup\<辞書名>-<パスのハッシュ>\`(`%LocalAppData%` が無ければ `%AppData%\MyDictionary\backup\`) |

### 3.2 辞書(SQLite)
1つの辞書は、1つの SQLite ファイルです。テーブルは `words` の1つだけです。

```sql
CREATE TABLE words (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    word       TEXT NOT NULL,              -- 見出し語
    meaning    TEXT NOT NULL,              -- 意味(改行は \n)
    tags       TEXT NOT NULL DEFAULT '',   -- タグ。スペース区切り(# は付けない)
    updated_at INTEGER NOT NULL,           -- 更新日時(UNIX 秒、UTC)
    link       TEXT NOT NULL DEFAULT '',   -- 参照先。改行区切り(1行に1つ)
    reading    TEXT NOT NULL DEFAULT ''    -- 読み
);
```

- ジャーナルは既定(DELETE)のまま。WAL は、共有フォルダで動かないため使わない。
- `busy_timeout` は 5 秒(`core::BUSY_TIMEOUT`)。

#### 版の記録(`user_version`)
SQLite にもとからある整数の欄 `PRAGMA user_version` に、**この辞書に書き込んだことのある、いちばん新しいアプリの版** を記録します(2.03 なら 203。`core::app_version_num` が、Cargo の版 `2.0.3` から `major * 100 + minor * 10 + patch` で作る)。

- 書き込みのたびに、`core::migrate` の中で、記録が自分の版より古ければ更新する(`core::stamp_version`)。新しければ、何もしない。
- 読み込みのときに記録を読み(`core::stored_version`)、自分の版より新しければ、起動中に1回だけ下段に知らせる(「全員が同じ版を使う」ための知らせ。書き込みは止めない)。
- 表や列は増えない。この欄を見ない版(2.02 以前)は、記録を変えないし、知らせも出さない。
- 将来、古い版が書くと壊れるような変更をするときは、この番号を見て書き込みを止める処理を足せる(いまは無い)。

#### 列の追加(移行)
`link` と `reading` は、後から追加した列です。

- **読むとき**: 列が無ければ、空文字として読む(`core::load_all`)。参照のみで開いた古い辞書も読める。
- **書くとき**: 書き込みの直前に、無い列を `ALTER TABLE … ADD COLUMN` で足す(`core::migrate`。`safe::write` の中で呼ぶ)。
- 列を足すだけなので、古い版のアプリからも引き続き読み書きできる。

今後、列を増やすときも、この方式(既定値付きの列を足す、読むときは無くても動く)に従ってください。

### 3.3 メモリ上の語(`core::Entry`)
| 項目 | 内容 |
|---|---|
| `dict` | 辞書の添字(設定での並び順) |
| `id`, `word`, `reading`, `meaning`, `tags`, `link`, `updated_at` | DB の列と同じ |
| `word_lc`, `meaning_lc`, `reading_norm` | 検索用に文字をそろえたもの(`core::fold`。[4.1](#41-文字をそろえるcorefold)) |
| `tags_lc` | タグの文字をそろえ、各タグの頭に `#` を付けたもの(例: `#it #略語`) |

語を識別するのは `(dict, id)` の組です。`st.entries` の添字は、登録・編集・削除や読み直しのたびに変わるので、保持してはいけません。

### 3.4 しおり(`bookmarks.tsv`)
1行に1つ、タブ区切りです。

```
辞書のパス<TAB>id<TAB>見出し語<TAB>追加日時(UNIX 秒)
```

- 辞書のパスは、大文字小文字を区別せずに比べる。
- 見出し語は、控えとして残しているだけで、照合には使わない。
- 同じ秒に続けて付けても順番が保たれるよう、追加日時は既存の最大より後にする。
- 保存は、別名で書いてから置き換える。
- 語を削除したとき、その語のしおりも外す。

### 3.5 バックアップ
| ファイル | 内容 |
|---|---|
| `pre-write.db` | 最後の書き込みの直前の状態 |
| `latest.db` | 最後の書き込みが成功した直後の状態 |
| `gen-<UNIX 秒>.db` | 世代バックアップ。前回から 600 秒以上たっていたら作る。10 個を超えたら古いものを消す |

フォルダ名は、`<ファイル名の拡張子を除いた部分>-<パス全体(小文字)の FNV-1a ハッシュの下位32ビット、16進8桁>` です。

## 4. 検索

実装は `core::filter_in` です。条件は `core::Query` で渡します。

| 項目 | 内容 |
|---|---|
| `all` | 全体検索(検索欄) |
| `word` | 絞り込みの「見出し語・読み」 |
| `meaning` | 絞り込みの「意味」 |
| `tag` | 絞り込みの「タグ」 |
| `dicts` | 検索する辞書(添字ごとの真偽)。`None` なら全部 |

### 4.1 文字をそろえる(`core::fold`)
語の側(見出し語・読み・意味・タグ)と検索語の両方を、同じ規則でそろえてから比べます。語の側は、読み込みのときに一度だけそろえます。

| そろえるもの | 内容 |
|---|---|
| 大文字・小文字 | 1文字ずつ小文字にする |
| 全角の英数字・記号 | U+FF01〜U+FF5E を半角にする。全角スペース(U+3000)は半角スペースにする |
| 半角カタカナ | U+FF61〜U+FF9F を全角にする |
| カタカナ | ひらがなにする(ァ〜ヶ、ヽ ヾ) |
| 濁点・半濁点 | 別の文字になっているもの(半角の `ﾞ` `ﾟ`、結合文字 U+3099 / U+309A、単独の `゛` `゜`)は、前の字と1文字に合成する(「ｶﾞ」→「が」)。合成できない位置のものは、そのまま残す |

- 長音や小さい字の違い、濁点の有無はそろえない。
- 合成で文字数が変わるので、「1文字が1文字に対応する」とは限らない。強調表示の位置は、そろえた各文字に元の位置を持たせて求める(`fold_spans`。[4.7](#47-強調表示))。
- 同じ見出し語かどうかの判定(登録時の重複の知らせ、リンクでの移動)も、`fold` した見出し語(`Entry::word_norm`)で行う。

### 4.2 語の区切りと節(`core::parse_clauses`)
- `all` `word` `meaning` は、空白で区切る。`tag` は、空白・カンマ・読点(`,` `，` `、`)で区切る。
- 区切った語を、**節** の列にする。節は「選択肢(`alts`)のどれかに一致すればよい」というまとまりで、節どうしは AND。

| 入力 | 節 |
|---|---|
| `a b` | [a] かつ [b] |
| `a|b`、`a OR b`、`a | b`、`a |b`、`a| b` | [a か b] |
| `-a` | [a でない] |
| `-a|b` | [a でも b でもない] |

- `OR` は、大文字(`OR` `ＯＲ`)のときだけ記号として扱う。`fold` すると小文字と区別できなくなるので、そろえる前に判定する。
- `-` は、語の先頭にあるときだけ除外とする(全角の `－` も、`fold` で `-` になる)。
- 次のものは、入力の途中とみなして無視する: `#` や `*` だけの語、`-` だけの語、`|` だけの語、行末の `OR`、空の選択肢(`a|` の後ろ側)。空の選択肢を「すべてに一致」とはしない。
- 除外の節と、前後の節を `OR` でつなぐことはしない(別々の節として扱う)。

### 4.3 一致の条件
すべての節が、次の場所で条件を満たす語だけが残ります。

| 欄 | 当てる場所 |
|---|---|
| `all` | 見出し語、読み、意味、タグのどれか |
| `word` | 見出し語、または読み |
| `meaning` | 意味 |
| `tag` | タグ |

### 4.4 語の種類(`core::Term`)
| 種類 | 条件 | 見出し語・読み | 意味 | タグ |
|---|---|---|---|---|
| 通常 | `*` を含まない | 部分一致 | 部分一致 | `tags_lc`(`#a #b`)に対する部分一致 |
| ワイルドカード | `*` を含む | 全体に照合 | 断片が順に現れる | タグ1つずつに、全体を照合 |
| タグの完全一致 | `#"名前"`(タグ欄では `"名前"` でもよい) | 一致しない | 一致しない | タグが、その名前そのもの |

- 通常の語で `#it` と書くと、`tags_lc` の中の `#it…` に一致するので、**タグの先頭一致** になる。
- ワイルドカードは、`*` で区切った断片が、重ならずにこの順で現れるかを調べる(`core::glob`)。先頭が `*` でなければ先頭を固定し、末尾が `*` でなければ末尾を固定する。
- ワイルドカードのタグ照合では、語が `#` で始まっていれば `#` 込みで、そうでなければ `#` を除いたタグ名と比べる。
- タグの完全一致は、タグの一覧と、本文のタグのクリックから検索するために足した(`core::tag_query` が作る)。`#it` では `item` などにも一致してしまうため。閉じる `"` を打つ前(入力の途中)は、引用符の無い語として扱う。

### 4.5 順位
検索語があるとき、次の順に並べます(同じ順位の中は、元の並びのまま)。基準にする節は、`word` の最初の節(除外でないもの)、無ければ `all` の最初の節(除外でないもの)です。除外の節しか無いときは、すべて順位 3 です。

| 順位 | 条件 |
|---|---|
| 0 | 見出し語または読みが、入力全体と完全に一致。基準の節に選択肢が複数あるときは、そのどれかと完全に一致 |
| 1 | 見出し語または読みが、基準の語で始まる(ワイルドカードの場合は、見出し語または読みに一致) |
| 2 | 見出し語または読みに、基準の語が含まれる |
| 3 | それ以外 |

基準の節に選択肢が複数あるときは、選択肢ごとの順位のうち、いちばん良いものを使います。

### 4.6 結果の再利用
文字を足しただけの入力では、前回の結果の中だけを調べ直します(`core::narrows`)。

- 条件: 辞書の選択が同じで、4つの欄のすべてで、新しい文字列が前の文字列で始まっている。**`fold` でそろえた後の文字列で比べる**(「ｶ」に濁点を足した「ｶﾞ」は「が」で、「か」の結果の部分集合ではない)。
- ワイルドカード(`*`)、OR(`|` `OR`)、除外(`-` で始まる語)を含むときは使わない。文字を足すと一致の範囲が広がることがあるため(`-a` → `-ab` は除外が減る。`a O` → `a OR` は条件が1つ減る)。
- **`st.entries` を変更したときは、必ず `st.last_query = None` にすること**。前回の結果は添字で持っているため、語の並びが変わると無効になる(登録・編集・削除・読み直し・しおり表示の切替)。

### 4.7 強調表示
`Query::mark_terms` が、見出し語用・意味用・タグ用の語を返します。`core::mark_ranges` が、文字列の中の一致範囲を UTF-16 単位で返します(重なる範囲はまとめる)。

- 検索と同じく `fold` でそろえて照合し、範囲は **元の文字列の上の位置** で返す。「ｶﾞ」のように2文字が1文字に合成された部分は、2文字ぶんの範囲になる。
- OR の選択肢は、すべて強調する。除外の語は、強調しない。
- ワイルドカードの語は、`*` で区切った断片ごとに強調する。英数字1文字だけの断片は、強調しない。

## 5. 並び順

### 5.1 見出し語順(`core::sort_entries`)
読み込み直後と、登録・編集の後に、`st.entries` 全体をこの順に並べます。並べ替えのキーは次のとおりです。

| 見出し語の先頭 | キー |
|---|---|
| ASCII の英数字 | 見出し語(`word_lc`)。読みがあっても使わない |
| それ以外 | 読みがあれば読み(`reading_norm`)、無ければ見出し語(`word_lc`) |

- どちらも `fold` 済みなので、カタカナはひらがなと同じ扱いになり、全角の英数字は英数字として、半角カタカナはかなとして並ぶ。
- 文字コードの順で比べるので、数字 → 英字 → かな → 漢字 の順になる。
- キーが同じときは、見出し語(`word_lc`)、辞書の添字、id の順で決める。

### 5.2 そのほかの並び順(`config::Sort`)
検索の結果(`st.matches`)に対して、安定ソートで並べ替えます。

| 値 | 内容 | 設定への保存 |
|---|---|---|
| `Word` | 並べ替えない(見出し語順、または検索の順位のまま) | する(`word`) |
| `UpdatedAsc` | 更新日時の昇順 | する(`updated_asc`) |
| `UpdatedDesc` | 更新日時の降順 | する(`updated_desc`) |
| `Bookmark` | しおりの追加日時の昇順 | しない |

しおり表示に入ると `Bookmark` に切り替え、出ると元の並び順に戻します。

## 6. 書き込みの安全手順

登録・編集・削除・取り込みは、すべて `safe::write(db, backup_root, f)` を通します。`f` の中の変更は、1つのトランザクションです。

| 手順 | 内容 | 失敗したとき |
|---|---|---|
| 1 | `BEGIN IMMEDIATE` で書き込みロックを取る(最大5秒待つ) | `Busy` |
| 2 | `PRAGMA quick_check` で、書き込み前の整合性を調べる | `CorruptBefore`(書き込まない) |
| 3 | 別の接続から、バックアップ API で `pre-write.db` へスナップショット。必要なら世代バックアップ | `Backup`(書き込まない) |
| 4 | `core::migrate` の後、`f` を実行してコミット | `Conflict` / `Sql`(ロールバックされる) |
| 5 | ファイルを開き直して `quick_check` | 壊れていたら `pre-write.db` から復元 → `RolledBack`。復元も失敗したら `RestoreFailed` |
| 6 | 成功後の状態を `latest.db` へスナップショット(失敗しても結果には影響させない) | — |

- 手順3 でロックを取った後にスナップショットを取るのは、ほかの人の変更をすべて含んだ状態を残すため。
- 復元(`safe::restore`)は、バックアップ自体を検査した後、同じフォルダに一時ファイルを作ってから置き換える。残っているジャーナルは消す。
- 復元に使うバックアップ(`safe::latest_backup`)は、検査に通るもののうち最も新しいもの。時刻が同じなら `latest` > `pre-write` > 世代 の順。

### 編集の衝突
`core::update` は、`WHERE id = ? AND updated_at = ?` で、読み込んだ時点の更新日時と一致するときだけ更新します。一致しなければ `Conflict` とし、上書きしません。同じ秒の中で続けて編集しても更新日時が変わるよう、新しい値は `max(現在, 以前 + 1)` にします。

この仕組みは、**「(id, 更新日時) が同じなら、内容も同じ」** という関係に頼っています。内容を書き換える処理(取り込みの上書きなど)を足すときは、必ず更新日時も変えてください。

### 直前の操作を元に戻す(`undo.rs`)
書き込みのときに、変える前の内容を `undo::Undo` に控え、`undo::revert` でその逆を行います。

| 操作 | 控えるもの | 元に戻すとき |
|---|---|---|
| 追加(登録、取り込みの追加) | id と、書き込んだ更新日時 | `DELETE … WHERE id = ? AND updated_at = ?` |
| 削除 | 消す前の全項目(`undo::delete_with_snapshots` が、トランザクションの中で読んでから消す) | 同じ id で `INSERT`(その id がすでにあれば、入れない) |
| 書き換え(編集、取り込みの上書き) | 変える前の全項目と、書き込んだ後の更新日時 | `UPDATE … WHERE id = ? AND updated_at = 書き込んだ後の値` で、前の内容に戻す。**更新日時も前の値に戻す** |

- `WHERE` の条件に合わなかった語(ほかの人がその後に変更・削除した語)は戻さず、`Reverted::skipped` に数える。
- 削除した語を同じ id で入れ直せるのは、`words.id` が `AUTOINCREMENT` で、消した id が使い回されないため。id が同じなので、しおりもそのまま有効になる。
- 更新日時を前の値に戻してよいのは、上の「(id, 更新日時) が同じなら、内容も同じ」が保たれるため。変更後の内容を読み込んでいた人の編集は、更新日時が違うので衝突になる。変更前の内容を読み込んでいた人の編集は、同じ内容に対するものなので通る。
- 画面の側(`gui::UndoOp`)は、直前の1回ぶんだけを持つ。辞書はパスで持ち(設定で辞書の並びが変わっても探せるように)、削除と一緒に外したしおりも控える。起動中だけ有効。
- 元に戻すのも `safe::write` を通す。終わったら、辞書を読み直す。
- 設定の画面で行った取り込みは、`SettingsDlg::undo` で呼び出し側に渡す。

### ほかの人の変更の検知
- 読み込み時に、辞書ごとのファイルの(更新時刻, サイズ)を控える(`safe::file_stamp`)。
- ウィンドウが前面に出たとき(`WM_ACTIVATE`)、控えと違っていれば読み直す。
- 書き込みの前に控えと違っていたら、書き込みの成功後に読み直す(メモリ上の内容が古いため)。

### 起動時の破損
読み込みで、破損を示すエラー(`SQLITE_CORRUPT` / `SQLITE_NOTADB`)が出た辞書は、復元するかを確認します。同じ辞書について確認するのは、1回の起動につき1度だけです。

## 7. 取り込みと書き出し

### 7.1 JSON(`json_io.rs`)
```json
{
  "format": "MyDictionary",
  "version": 1,
  "entries": [
    {
      "word": "一期一会",
      "reading": "いちごいちえ",
      "meaning": "一生に一度の出会い。\nその機会を大切にすべきだという教え。",
      "tags": ["四字熟語"],
      "links": ["公式サイト | https://example.com/", "[[温故知新]]"],

      "updated_at": 1730000000,
      "updated": "2024/10/27 12:33:20"
    }
  ]

```

**書き出し**: 項目の順番を保つため、文字列を手で組み立てています(エスケープだけ `serde_json` を使う)。辞書ファイルを読み直して、見出し語順で出力します。

**取り込み**:
| 項目 | 扱い |
|---|---|
| 全体 | 配列、または `entries` に配列を持つオブジェクト |
| `word`, `meaning` | 必須。無い項目は読み飛ばす |
| `tags` | 文字列の配列、または区切り文字入りの文字列 |
| `links` | 文字列の配列。無ければ `link`(文字列、改行区切り)を見る |
| `reading` | 任意 |
| `updated_at` | 正の整数なら、追加する語の更新日時として使う。無ければ取り込んだ時刻 |
| `id` | 語の番号。`updated_at` とそろっていれば、上書きの照合に使う([7.3](#73-取り込みの手順importimport_rows)) |
| `updated` など、そのほかの項目 | 無視する |

`tags` `links`(`link`) `reading` は、キーがあるかどうかを控えます(`import::Given`)。上書きのとき、キーの無い項目は今の値を残します。

### 7.2 CSV / TSV(`import.rs`)
| 項目 | 内容 |
|---|---|
| 文字コード | UTF-8(BOM の有無どちらも)、UTF-16(BOM 付き)。どちらでもなければ Shift_JIS(CP932)として読む(`dialogs::decode_text`) |
| 区切り | 拡張子が `.tsv` `.tab` ならタブ、`.csv` ならカンマ。それ以外は、1行目にタブがあればタブ |
| 引用 | `"..."` で囲める。中の `""` は `"` 1つ。区切り文字と改行を含められる |
| 見出し行 | 1行目に、見出し語と意味の両方の列名があれば、列名で対応づける |
| 見出し行が無いとき | 左から 見出し語、意味、タグ、参照先、読み |
| 改行の表記 | **タブ区切りで、`"..."` で囲んでいない値に限り**、意味と参照先の中の `\n`(バックスラッシュと n)を改行に変える。CSV と、囲んだ値では、書いたとおりに扱う(書き出したファイルを取り込んだときに、内容が変わらないようにするため) |
| 空の行 | 読み飛ばす。見出し語か意味が空の行は、件数を数えて読み飛ばす |

列名(大文字小文字は区別しない):

| 列 | 名前 |
|---|---|
| 見出し語 | 見出し語、見出し、単語、語、word、term、headword |
| 意味 | 意味、説明、meaning、definition、description |
| タグ | タグ、tag、tags |
| 参照先 | 参照先、リンク、link、links、url |
| 読み | 読み、よみ、読み方、ふりがな、reading、yomi、kana |
| 管理用 | 管理用、管理番号、key(列名の後ろの括弧書きは無視する。書き出しでは「管理用(変更しない)」) |

見出し行に列があるか(見出し行の無い表では、どこかの行にその列まであるか)を控えます(`import::Given`)。

**書き出し**(`import::export_table`): 見出し語・読み・意味・タグ・参照先・更新日時・管理用 の順。UTF-8(BOM 付き)、行末は CRLF。区切り文字・引用符・改行・`\` を含む値と、前後に空白のある値は `"..."` で囲みます。更新日時は見るための列(日本時間)で、取り込みでは使いません。管理用の列は `<id>_<更新日時>` です。書き出して取り込むと内容が元に戻ることを、自動テストで確かめています。

### 7.3 取り込みの手順(`import::import_rows`)
`mode` で、同じ見出し語の語がすでにあるときの扱いを選びます。`dry` が真なら何も書かず、結果の見込み(`import::Outcome`)だけを返します。`safe::write` の中で実行するので、全体が1つのトランザクションです。

| `mode` | 動作 |
|---|---|
| `KeepBoth` | 見出し語と意味の組が、辞書の中またはファイルの中ですでに出ていれば読み飛ばし、ほかは追加する(これまでの動作) |
| `Overwrite` | 下の照合で決めた語を、ファイルの内容で置き換える |
| `Skip` | 管理用の番号の語か、同じ見出し語の語が辞書にあれば読み飛ばし、ほかは追加する |

**上書きの照合**
1. 行に管理用の番号 `(id, 更新日時)` があり、その id の語が辞書にある
   - 内容が同じ → 変更なし
   - 辞書の語の更新日時が、書き出した時点のまま → 上書き(見出し語が変わっていても、その語に当たる)
   - 更新日時が変わっている → 書き出した後にだれかが変更した語。上書きしない(`Outcome::conflicts`)
2. 番号が無い、またはその id の語が辞書に無い → 見出し語(完全一致)で照合する。相手にするのは、取り込む前から辞書にあった語で、ほかの行の番号で指されていない語
   - 辞書に無い → 追加
   - 辞書にもファイルにも、その見出し語が1件だけ → 内容が同じなら変更なし、違えば上書き
   - どちらかに複数ある → 「両方残す」の規則で扱う(`Outcome::ambiguous`)

- 上書きでは、ファイルに列(キー)のある項目だけを置き換える。列があって空なら、空にする。
- 上書きした語は id を変えず、更新日時を `max(現在, 以前 + 1)` にする([編集の衝突](#編集の衝突)の関係を保つため)。
- 番号だけで照合しないのは、別の辞書から書き出したファイルを取り込んだときに、たまたま同じ id の語を上書きしないため(更新日時まで一致することは、まず無い)。
- 画面(`dialogs::import_into`)は、3つの `mode` の見込みを先に出して、選択肢つきの確認画面(TaskDialog。`dialogs::ask_import_mode`)に件数を表示する。実行は書き込みの中でもう一度照合し直す(確認している間に、ほかの人が変更しているかもしれないため)。
- 戻り値の `undo::Undo` で、取り込みを元に戻せる([直前の操作を元に戻す](#直前の操作を元に戻すundors))。

### 7.4 JSON かどうかの判定
拡張子が `.json`、または内容(BOM と空白を除く)が `[` か `{` で始まっていれば、JSON として読みます。

### 7.5 サンプル
`sample/sample.tsv` と `sample/sample2.tsv` は、取り込める TSV の見本です(列名付き)。実行ファイルには含めていません。
自動テストでは、この2つのファイルが正しく解析でき、取り込めること、文中の `[[語]]` のリンク先が実在することを確かめています。

## 8. リンク

### 8.1 参照先の欄(`core::parse_links`)
1行に1つ。次の順に解釈します。

| 形 | 表示名 | 開く先 |
|---|---|---|
| `[[語]]` | 語 | `word:語` |
| `[表示名](開く先)` | 表示名 | 開く先 |
| `表示名 \| 開く先`(最初の `\|` で分ける。両側が空でないとき) | 表示名 | 開く先 |
| それ以外 | 行全体 | 行全体 |

### 8.2 意味の文中(`core::parse_body`)
意味の文を解析して、**表示する文字列**(記法を取り除いたもの)と、リンク・画像の範囲(UTF-16 単位)を返します(`core::Body`)。

| 記法 | 表示 | 扱い |
|---|---|---|
| `[[語]]` | 語 | `word:語` へのリンク。同じ行の中で閉じていて、中身が空でないもの |
| `[表示名](開く先)` | 表示名(空なら開く先) | リンク。**開く先が `core::is_link_target` のときだけ**(下記) |
| `![説明](パス)` | 説明(空ならファイル名) | 画像。範囲を `Body::images` に入れ、同じ範囲を `img:パス` へのリンクにもする。パスが `http(s)://` なら画像にせず、その URL へのリンクにする(通信しないため) |
| `http://…` `https://…` | そのまま | リンク。空白、和文の括弧・句読点、`<` `>` `"` の手前まで。末尾の `. , ; : ! ? ) ] '` は含めない |

- `[表示名](開く先)` の開く先として扱うのは、`scheme://…`、`mailto:`、`word:`、絶対パス(`C:\…` `\\サーバー\…`)、`.\` `..\` で始まる相対パスだけ。条件を付けないと、`funcs[0](x)` のような文がリンクになるため。画像は `!` で始まるので、この条件は付けない。
- 表示名と開く先は、同じ行の中で閉じていること。開く先は、対応する `)` まで(中の括弧は、対になっていればよい)。空白や日本語を含んでよく、`<…>` や `"…"` で囲んであれば外す。バックスラッシュは、ただの文字(パスの区切り)として扱う。
- 記法として読めなかった `[` は、そのまま表示する。
- **検索・強調表示・候補リストの抜粋は、表示する文字列に対して行う**(`core::display_text`。語の読み込みのときに、意味に `[` があるものだけ解析する)。開く先やパスは、検索の対象にならない。記法をまたぐ語句(`これは[[りんご]]です` を「りんごです」で)も引ける。

**相対パスの基準**(`core::resolve_path`): スキームの付いていない、絶対パスでもない開く先は、その語の辞書ファイルのあるフォルダを基準にする。参照先の欄のリンクも同じ(開くときに `gui::open_link` が直す)。

### 8.2b 画像(`pics.rs` と、`gui.rs` の `show_pic` まわり)
- 本文は、まず説明の文字(リンク)で表示する。画像は別スレッドで読み(`gui::start_pics`。遅い共有フォルダでも画面を止めない)、1枚ずつ `WM_APP_IMAGE` で受け取って、**説明の文字の範囲を画像に置き換える**(`gui::show_pic`)。
- 置き換えると文字位置がずれる(説明の文字数 → 画像の1文字)ので、後ろにあるリンク(`State::links`)と画像(`State::img_slots`)の位置を、その分だけ動かす。
- 本文を表示し直すたびに番号(`State::detail_gen`)を増やし、前の表示のための画像は捨てる。読んだ画像は 24 枚まで覚えておく(`State::pic_cache`。ファイルの更新時刻が変わっていたら読み直す)。
- 表示の大きさは、本文欄の幅に収める(`pics::fit`。拡大はしない)。ウィンドウの大きさを変え終えたとき(`WM_EXITSIZEMOVE`、最大化など)に、幅が変わっていれば表示し直す。
- 種類と大きさは、ファイルの先頭から自前で読む(`pics::probe`。PNG・JPEG・GIF・BMP)。20MB を超えるファイル、21 枚目以降は表示しない。
- **自動で読むのは、ファイルのパスだけ**(`pics::loadable`。ドライブ、共有フォルダ、相対パス)。通信しない方針のため、スキームの付いたもの(`file://` など)、`\\サーバー@SSL\…` `\\サーバー@8080\…`(共有フォルダではなく、HTTP の WebDAV でつながる形)、`\\.\` `\\?\` で始まる形は読まず、説明の文字のリンクのままにする。判定は、書かれたとおりのパスで行う(相対パスを、辞書のフォルダを基準に直す前)。
  - 共有フォルダの形(`\\サーバー\共有\…`)は読む。Windows が、つながらなかった共有フォルダを WebDAV で試すことがあるが、これはアプリからは止められない。
- ほかの語に移ったら、読み込みのスレッドは、残りの画像を読まずに終わる(`detail_gen` をスレッドからも見る)。
- クリックの判定は、画像については表示している大きさで行う(`gui::link_at`)。拡張子が画像で、自動で読めるパス(`pics::loadable`)のものは、確認なしで開く。それ以外(`![x](a.exe)`、`![x](file://…/a.png)` のようなもの)は、ふつうのリンクと同じ確認を通す。

**本文欄への入れ方**(`State::img_mode`)。最初の1枚で、使える方法を決める。

| 方法 | 内容 |
|---|---|
| 1 | `EM_INSERTIMAGE`(Windows 8 以降の RichEdit の機能)。ファイルの中身を、そのまま渡す |
| 2 | Windows の画像の部品(WIC)で読んで表示の大きさに縮小し、DIB にして、RTF(`\pict\dibitmap0`)で入れる。透明な部分は、背景色の上に重ねる(`pics::dib_from_pbgra`) |
| 3 | どちらも使えない。説明の文字のまま表示する |

- 「成功」が返っても何も起きない環境がある(Wine の `EM_INSERTIMAGE`)ので、**その位置の文字が画像になったか**(U+FFFC、または空白)と、文字数の変化で確かめる。思わぬ形で文字が変わったときは、方法 3 にして表示し直す。
- Wine の RichEdit は、`\dibitmap` の情報ヘッダを 44 バイトとして読むので、Wine の上では 4 バイト空ける(`gui::on_wine`)。
- **開発環境(Wine)で確かめられたのは、方法 2 だけ。方法 1 は、本物の Windows での確認が必要。**

**「画像を追加…」**(`dialogs::add_picture`、`pics::place`)
- 押した時点では、意味の欄に `![](<辞書のファイル名>_pic\<ファイル名>)` を入れるだけ(予定の名前。`pics::planned_path`)。コピーは、保存を押したときに行う(キャンセルしたときに、ファイルを残さないため。登録先の辞書を後から変えても、正しいフォルダに入る)。
- ファイル名は、記法とぶつかる括弧などを `_` に置き換え、長すぎるものは切り詰める(`pics::safe_name`)。
- 同じ名前のファイルがあるとき、中身が同じならそれを使い、違えば `名前-2` のように番号を付ける。新しいファイルは「無ければ作る」で作るので、2人が同時に追加しても上書きは起きない。番号が付いたときは、意味の欄のパスも合わせて直す。
- フォルダの名前は、辞書の表示名ではなくファイル名から作る(表示名は、人ごとに違うことがあるため)。

### 8.3 開く先の種類(`core::link_kind`)
| 種類 | 条件 | 動作 |
|---|---|---|
| `Word` | `word:` で始まる | アプリ内で移動する(検索欄をその語にし、完全に一致する語を選ぶ) |
| `Web` | `http://` `https://` で始まる | そのまま `ShellExecuteW` で開く |
| `Executable` | 拡張子が実行形式(下記) | 強い警告(既定は「いいえ」)の後に開く |
| `Other` | それ以外 | 確認の後に開く |

実行形式とみなす拡張子: `exe com bat cmd scr pif msi msp ps1 vbs vbe js jse wsf wsh hta lnk url reg jar cpl dll appref-ms`

`file:` 以外のスキーム(`mailto:` など。コロンの前が2文字以上)は、拡張子では判定せず `Other` とします。

### 8.4 クリックの判定
RichEdit の URL 自動検出(`EM_AUTOURLDETECT`)は使いません。URL の形をしていない表示名のリンク属性(`CFE_LINK`)を消してしまうためです。

- リンクの範囲と開く先を、`State::links` に持つ。
- `ENM_MOUSEEVENTS` を有効にし、`EN_MSGFILTER` でマウスの操作を受け取る。
- 左ボタンを離したとき、選択範囲が空なら(= ドラッグではなくクリックなら)、`EM_CHARFROMPOS` で文字位置を求め、`EM_POSFROMCHAR` で座標も確かめて、リンクの上かを判定する(`gui::link_at`)。
- 本文を書き換える処理を RichEdit のマウス処理の途中で行わないよう、`WM_APP_LINK` を自分に送ってから開く。
- リンクの上では、RichEdit をサブクラス化して `WM_SETCURSOR` を処理し、カーソルを指のマークにする。

- マウスがリンクの上にある間は、開く先をステータス欄に表示する(`State::hover_link`)。本文欄から出たことは、`TrackMouseEvent` で依頼した `WM_MOUSELEAVE` で知る。

`CFE_LINK` は、見た目(下線)のためだけに付けています。

| ボタン | 幅 108 × 高さ 36(`BTN_W`, `CTL_H`) |
| 1行の入力欄 | 高さ 36 |
| 候補リスト | 幅 320(固定)。1行の高さ 58 |

DPI が変わったとき(`WM_DPICHANGED`)は、フォントとリストの行の高さを作り直します。

### 9.2 部品
| 部品 | 実装 |
|---|---|
| ボタン | `BS_OWNERDRAW`。`ui::draw_button` が角丸で描く(Primary / Secondary / Danger / Toggle) |
| 入力欄 | 枠なしの `EDIT` を、親が描く角丸の枠の内側に置く(`ui::field`, `ui::paint_fields`)。フォーカス時は枠を青にする |
| 候補リスト | `SysListView32`(`LVS_OWNERDATA`、1列、見出しなし)。行は `NM_CUSTOMDRAW` で自前で描く(`gui::draw_row`)。行の高さは、空のイメージリストで確保する |
| 本文 | `RICHEDIT50W`(Msftedit.dll)。使えないときは `EDIT` で代用(`rich_ok`) |
| モーダル画面 | 専用のウィンドウクラスと、自前のメッセージループ(`dialogs::run_modal`) |

### 9.3 注意が必要な点
- **仮想リストの範囲選択**: Shift+クリックなどの範囲選択は、`LVN_ITEMCHANGED` ではなく `LVN_ODSTATECHANGED` で届く。両方を処理する。
- **Tab での移動**: 複数行の `EDIT` は、Tab での移動を親へ `WM_NEXTDLGCTL` で依頼する。通常のダイアログではないので、自分で処理する(`ui::next_dlg_ctl`)。
- **複数行の `EDIT` の Ctrl+A**: 標準では効かないので、メッセージループで補う(`ui::select_all_if_edit`)。
- **プログラムからの入力欄の変更**: `ui::set_text` は、`BUSY` カウンタを上げている間に設定する。`WM_COMMAND` の処理は、`BUSY` が上がっていれば通知を無視する(再入を避ける)。
- **状態の持ち方**: `State` は `GWLP_USERDATA` に置いた `Box` で、`gui::state` が `&mut` を返す。メッセージ処理は再入することがあるので、上の `BUSY` で、自分の操作が引き起こした通知を処理しないようにしている。

### 9.4 リンクでの移動と、戻る
- `[[語]]` などのリンクで別の語へ移動するとき(`gui::jump_to_word`)、移動する前の状態(検索欄と絞り込みの3欄の文字、絞り込みの開閉、しおり表示、選んでいた語)を `State::back` に積む。上限は 50(`BACK_MAX`)。
- Alt+←(`WM_SYSKEYDOWN`)とマウスの戻るボタン(`WM_XBUTTONUP` の XBUTTON1)を、メッセージループで `ID_BACK` のコマンドに変える。`gui::go_back` が、最後に積んだ状態を取り出して戻す。
- 起動中だけ持ち、保存はしない。辞書の構成が変わる読み直し(`start_load` の `keep = false`)では、辞書の添字が変わるので消す。
- 検索欄に入れる文字列は、見出し語そのままではなく `core::search_text_for` で作る。`-` で始まる語が除外として、`OR` が記号として解釈されるのを避けるため。完全一致の語は、`Entry::word_norm` で選ぶ。

### 9.5 登録時の重複の知らせ
- 登録・編集の画面を開くとき、読み込み済みの語から「そろえた見出し語 → (辞書の添字, id)」の索引を作って渡す(`gui::same_word_index`。編集中の語自身は除く)。
- 見出し語の欄が変わるたびに索引を引き、欄の下に件数を出す(`dialogs::update_dup`)。「その語を表示」は、画面を閉じて `EntryDlg::open_existing` で呼び出し側に知らせ、`gui::show_entry` がその語を表示する。
- 保存時は、登録先の辞書に同じ見出し語があるときだけ確認する(`dialogs::confirm_same_word`)。編集で見出し語を変えていないときは、たずねない。
- 索引は、画面を開いた時点の内容。ほかの人が直前に登録した語は拾えないことがある。

### 9.6 タグの一覧と、タグの一括変更
- タグと語数は、読み込み済みの語から数える(`core::tag_counts`)。書き方の違うタグは別々に数え、`fold` した名前の順に並べる(書き方の違うタグが隣り合う)。
- 一覧の画面(`dialogs::tags_dialog`)は、3か所から使う。

| 入口 | 動作 |
|---|---|
| 絞り込みのタグ欄の横の「一覧…」(`gui::do_tags`) | チェックしたタグを、タグ欄に `"名前"` の形で入れる。名前の変更・削除のボタンも出す |
| 本文のタグのクリック(`tag:` で始まるリンク。`gui::search_tag`) | 検索欄を `#"名前"` にする。移動する前の状態を控えるので、Alt+← で戻れる |
| 登録・編集の画面の「選ぶ…」 | チェックしたタグを、タグの欄に入れる。欄に書いてある、一覧に無いタグ(新しいタグ)は残す |

- 名前の変更・削除(`undo::retag`)は、タグを **書いたとおりの文字** で比べる(`IT` と `it` を1つにそろえられるように)。変更後のタグがすでに付いている語では、1つにまとまる。
- 書き換えた語は、更新日時を変える([編集の衝突](#編集の衝突)の関係を保つため)。変える前の内容を返すので、そのまま「元に戻す」の記録になる。
- 対象は、検索する辞書に入っている、書き込める辞書。参照のみの辞書の語は変えず、件数を知らせる。
- 画面の中で1行の入力が要るとき(新しい名前)は、`dialogs::prompt_dialog` を使う。この画面とタグの一覧は、`DM_GETDEFID` に答えているので、1行の欄で Enter を押すと OK になる。

### 9.7 独自のメッセージ
| メッセージ | 用途 |
|---|---|
| `WM_APP_LOADED` | 読み込みスレッドからの結果(`Box<Loaded>`)。世代番号(`gen`)が合わなければ捨てる |
| `WM_APP_TRAY` | トレイのアイコンの操作 |
| `WM_APP_SHOW` | 二重起動したときに、既存のウィンドウを表示させる |
| `WM_APP_LINK` | 本文のリンクがクリックされた(`Box<String>`) |

### 9.8 起動と終了
- 二重起動は、名前付きミューテックス(`Local\MyDictionarySingleInstance`)で検出する。2つ目は、既存のウィンドウに `WM_APP_SHOW` を送って終了する。
- 閉じるボタンと Esc(入力が空のとき)は、`close_to_tray` が真ならウィンドウを隠し、偽なら終了する。
- トレイのアイコンは、設定にかかわらず常に表示する。

## 10. 設定ファイル

INI 形式です(`config.rs`)。`;` または `#` で始まる行はコメントです。

| セクション | キー | 値 | 既定 |
|---|---|---|---|
| `[general]` | `hotkey` | `Ctrl+Alt+D` の形。`none` で無効 | `Ctrl+Alt+D` |
| | `close_to_tray` | `true` / `false` | `false` |
| | `sort` | `word` / `updated_asc` / `updated_desc` | `word` |
| | `title` | ウィンドウのタイトルに表示する名前。書いたとおりに表示する。空ならアプリの名前 | 空 |
| | `shared` | `true` / `false`。共用フォルダでの運用 | `false` |
| `[dictionary.<ID>]` | `name` | 表示名。省略すると ID | — |
| | `path` | 辞書のパス。必須 | — |
| | `readonly` | `true` / `false` | `false` |

- ホットキーは、修飾キー(`Ctrl` `Alt` `Shift` `Win`)を1つ以上と、キー(英数字、`F1`〜`F24`、`Space`)1つ。
- パスの中の `%名前%` は、環境変数に置き換える。相対パスは、設定ファイルのあるフォルダが基準。
- 辞書が1つも無ければ、既定の辞書(`dictionary.db`)を使う。
- 解釈できない行は無視し、警告として画面の下段に出す(起動は止めない)。
- 廃止したキー `timing_log` は、警告を出さずに無視する。
- 設定画面で保存すると、ファイル全体を書き直す(`config::to_ini`)。コメントは残らない。設定ファイルと同じフォルダの辞書は、ファイル名だけで書く。

### 共用フォルダでの運用(`shared = true`)
設定ファイルを複数人で使うことを示すフラグです。設定ファイルの場所(実行ファイルの隣か、`%AppData%` か)とは独立しています。

| 項目 | 動作 |
|---|---|
| しおり | 読み込まない・保存しない。ボタンと右クリックの項目を出さない。Ctrl+D は案内だけ出す |
| 並び順 | 変えても設定ファイルに書かない |
| 設定の保存 | 確認を出してから書く |
| タイトル | 変えない(`title` の値だけで決まる。`config::window_title`) |

フラグを切り替えたとき(設定の保存、設定ファイルの再読み込み)は、しおりを読み直し、部品の表示とレイアウトを更新します(`gui::apply_mode`)。

設定画面のホットキーの欄(`msctls_hotkey32`)は、Win キーを扱えません。欄を変更しなかった場合は、元の値(Win キーを含む)をそのまま残します。

### 版を上げてリリースする
1. 次の3か所の版をそろえて変える。
   - `Cargo.toml` の `version`
   - `app.rc` の `FILEVERSION` / `PRODUCTVERSION` と、`FileVersion` / `ProductVersion`
   - `src/ui.rs` の `APP_VERSION`
2. `docs/release-notes.md` を、その版の内容に書き換える。依存を更新したときは、`python tools/third_party_notices.py` で `THIRD-PARTY-NOTICES.txt` も作り直す。
3. 既定のブランチに反映する。
4. GitHub の Actions の画面で「release」→「Run workflow」を選び、`tag` に `v2.00` のようなタグ名を入れて実行する
   (`v2.00` のようなタグを push しても、同じ処理が動く)。

GitHub Actions(`.github/workflows/release.yml`)が Windows 上でテストとビルドを行い、タグと Release を作って `MyDictionary.exe`・`LICENSE`・`THIRD-PARTY-NOTICES.txt` を添付します。
`tag` を空にして実行すると、Release は作らず、ビルドした exe を Artifacts に残すだけです(Windows でのビルド確認に使えます)。
同じタグの Release を作り直したいときは、`replace` にチェックを入れて実行します(古い Release とタグを削除してから作成します)。

不要になった Release は、Actions の画面で「delete-release」→「Run workflow」を選び、タグ名を入れて実行すると、Release とタグの両方が削除されます(`.github/workflows/delete-release.yml`)。

## 13. 既知の制約

| 項目 | 内容 |
|---|---|
| 共有フォルダ | SQLite の性質上、同時書き込みによる破損を完全には防げない。安全手順は、破損の検出と復元のためのもの |
| バックアップ | その PC から書き込んだときだけ作られる。復元の瞬間にほかの人が書き込んでいる場合の競合は防げない |
| 読み | 自動では付かない。ローマ字の入力は、かなの読みに一致しない |
| 五十音順 | 文字コードに基づく簡易なもの。長音や小さい字の扱いは、国語辞典と一致しない。読みの無い漢字の語は、最後にまとまる |
| 表記の違い | 長音や小さい字の違い(「サーバ」と「サーバー」)、濁点の有無は、別の語として扱う |
| 検索の記法 | `-` で始まる語は、そのままでは引けない(除外として扱われる)。先頭の `-` を外して引く。引用符で囲む書き方は無い |
| ホットキー | 設定画面では Win キーを指定できない(設定ファイルでは可能) |
| しおり | 書き出しに含まれない。辞書のパスを変えると、付けたしおりは表示されなくなる |
| 元に戻す | 直前の1回だけ。起動中だけ有効。やり直し(元に戻したことの取り消し)は無い |
| 版の知らせ | 「新しい版のアプリでも使われています」の知らせは、版を記録する機能のある版どうしでだけ働く(2.02 以前の版は、記録も知らせもしない) |
| タグの入力 | 打っている途中に候補を出す機能は無い(登録の画面の「選ぶ…」で、一覧から選ぶ) |
| CSV と Excel | Excel は、開いたときに `-` `=` で始まる値や `0123` `1-2` のような値を、数式・数値・日付に変えることがある。その状態で保存して上書きの取り込みをすると、内容が変わる。書き出す側での対策は入れていない(実際の Excel での確認が必要) |
| 表示 | ダークモードには対応していない |
| 画像 | 画像は、辞書ファイルの中には入れない(ファイルのパスを書く)。書き出しにもバックアップにも含まれない。URL の画像は表示しない。GIF は動かない |
| 書式 | 見出し・太字・箇条書き・表などの書式は無い(意味の文中で使える記法は、リンクと画像だけ) |
| 署名 | 実行ファイルに署名が無い。Smart App Control が有効な PC では、起動やビルドがブロックされることがある |
| 状態の扱い | メッセージ処理の再入を `BUSY` カウンタで避けている。新しい通知を処理に加えるときは、自分の操作が引き起こす通知を無視できているかを確認すること |
