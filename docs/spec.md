## 1. 概要

| 項目 | 内容 |
|---|---|
| 目的 | 起動してすぐ引ける、個人・小さなチーム向けの辞書 |
| 対象 | Windows 10 / 11(64ビット) |
| 言語 | Rust(edition 2021) |
| GUI | Win32 API を直接使用(`windows` クレート 0.58)。標準コントロール + 一部を自前で描画 |
| 保存 | SQLite(`rusqlite` 0.32、`bundled` で静的リンク) |
| 配布 | 実行ファイル1つ(`MyDictionary.exe`、約1.7MB)。依存は Windows 標準の DLL のみ |
| ライセンス | MIT |
| 版 | 2.00(Cargo のパッケージは `mydictionary` 2.0.0) |

### 設計の方針
- **起動を待たせない**: ウィンドウを先に出し、辞書の読み込みは別スレッドで行う。
- **検索はメモリ上で行う**: 起動時に全件を読み込み、入力のたびにメモリ上を絞り込む。SQL での検索はしない。
- **画面に依存しない部分を分ける**: 検索・保存・取り込みなどは、Windows 以外でもビルドとテストができる。
- **壊れにくさ**: 書き込みは必ず [安全手順](#6-書き込みの安全手順) を通す。

## 3. データ

### 3.1 保存場所
| 種類 | 場所 |
|---|---|
| 設定 | 実行ファイルと同じフォルダの `MyDictionary.ini`(あれば)。無ければ `%AppData%\MyDictionary\MyDictionary.ini` |
| 辞書 | 設定で指定したパス。既定は、設定ファイルと同じフォルダの `dictionary.db` |
| しおり | 設定ファイルと同じフォルダの `bookmarks.tsv` |
| バックアップ | `%LocalAppData%\MyDictionary\backup\<辞書名>-<パスのハッシュ>\`(`%LocalAppData%` が無ければ `%AppData%\MyDictionary\backup\`) |

### 3.2 辞書(SQLite)
1つの辞書は、1つの SQLite ファイルです。テーブルは `words` の1つだけです。

```sql
CREATE TABLE words (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    word       TEXT NOT NULL,              -- 見出し語
    meaning    TEXT NOT NULL,              -- 意味(改行は \n)
    tags       TEXT NOT NULL DEFAULT '',   -- タグ。スペース区切り(# は付けない)
    updated_at INTEGER NOT NULL,           -- 更新日時(UNIX 秒、UTC)
    link       TEXT NOT NULL DEFAULT '',   -- 参照先。改行区切り(1行に1つ)
    reading    TEXT NOT NULL DEFAULT ''    -- 読み
);
```

- ジャーナルは既定(DELETE)のまま。WAL は、共有フォルダで動かないため使わない。
- `busy_timeout` は 5 秒(`core::BUSY_TIMEOUT`)。

#### 列の追加(移行)
`link` と `reading` は、後から追加した列です。

- **読むとき**: 列が無ければ、空文字として読む(`core::load_all`)。参照のみで開いた古い辞書も読める。
- **書くとき**: 書き込みの直前に、無い列を `ALTER TABLE … ADD COLUMN` で足す(`core::migrate`。`safe::write` の中で呼ぶ)。
- 列を足すだけなので、古い版のアプリからも引き続き読み書きできる。

今後、列を増やすときも、この方式(既定値付きの列を足す、読むときは無くても動く)に従ってください。

### 3.3 メモリ上の語(`core::Entry`)
| 項目 | 内容 |
|---|---|
| `dict` | 辞書の添字(設定での並び順) |
| `id`, `word`, `reading`, `meaning`, `tags`, `link`, `updated_at` | DB の列と同じ |
| `word_lc`, `meaning_lc` | 小文字にしたもの(検索用) |
| `reading_norm` | 読みを小文字にし、カタカナをひらがなにそろえたもの |
| `tags_lc` | タグを小文字にし、各タグの頭に `#` を付けたもの(例: `#it #略語`) |

語を識別するのは `(dict, id)` の組です。`st.entries` の添字は、登録・編集・削除や読み直しのたびに変わるので、保持してはいけません。

### 3.4 しおり(`bookmarks.tsv`)
1行に1つ、タブ区切りです。

```
辞書のパス<TAB>id<TAB>見出し語<TAB>追加日時(UNIX 秒)
```

- 辞書のパスは、大文字小文字を区別せずに比べる。
- 見出し語は、控えとして残しているだけで、照合には使わない。
- 同じ秒に続けて付けても順番が保たれるよう、追加日時は既存の最大より後にする。
- 保存は、別名で書いてから置き換える。
- 語を削除したとき、その語のしおりも外す。

### 3.5 バックアップ
| ファイル | 内容 |
|---|---|
| `pre-write.db` | 最後の書き込みの直前の状態 |
| `latest.db` | 最後の書き込みが成功した直後の状態 |
| `gen-<UNIX 秒>.db` | 世代バックアップ。前回から 600 秒以上たっていたら作る。10 個を超えたら古いものを消す |

フォルダ名は、`<ファイル名の拡張子を除いた部分>-<パス全体(小文字)の FNV-1a ハッシュの下位32ビット、16進8桁>` です。

## 4. 検索

実装は `core::filter_in` です。条件は `core::Query` で渡します。

| 項目 | 内容 |
|---|---|
| `all` | 全体検索(検索欄) |
| `word` | 絞り込みの「見出し語・読み」 |
| `meaning` | 絞り込みの「意味」 |
| `tag` | 絞り込みの「タグ」 |
| `dicts` | 検索する辞書(添字ごとの真偽)。`None` なら全部 |

### 4.1 語の区切り
- `all` `word` `meaning` は、空白で区切る。
- `tag` は、空白・カンマ・読点(`,` `，` `、`)で区切る。
- すべて小文字にしてから比べる。
- `#` と `*` だけでできた語は、検索語として扱わない(入力の途中とみなす)。

### 4.2 一致の条件
すべての語が、次の条件を満たす語だけが残ります(AND)。

| 欄 | 当てる場所 |
|---|---|
| `all` | 見出し語、読み、意味、タグのどれか |
| `word` | 見出し語、または読み |
| `meaning` | 意味 |
| `tag` | タグ |

読みに当てるときは、検索語のカタカナもひらがなにそろえます(`core::to_hiragana`)。見出し語・意味・タグは、表記どおりに比べます。

### 4.3 語の種類(`core::Term`)
| 種類 | 条件 | 見出し語・読み | 意味 | タグ |
|---|---|---|---|---|
| 通常 | `*` を含まない | 部分一致 | 部分一致 | `tags_lc`(`#a #b`)に対する部分一致 |
| ワイルドカード | `*` を含む | 全体に照合 | 断片が順に現れる | タグ1つずつに、全体を照合 |

- 通常の語で `#it` と書くと、`tags_lc` の中の `#it…` に一致するので、**タグの先頭一致** になる。
- ワイルドカードは、`*` で区切った断片が、重ならずにこの順で現れるかを調べる(`core::glob`)。先頭が `*` でなければ先頭を固定し、末尾が `*` でなければ末尾を固定する。
- ワイルドカードのタグ照合では、語が `#` で始まっていれば `#` 込みで、そうでなければ `#` を除いたタグ名と比べる。

### 4.4 順位
検索語があるとき、次の順に並べます(同じ順位の中は、元の並びのまま)。基準にする語は、`word` があればその最初の語、無ければ `all` の最初の語です。

| 順位 | 条件 |
|---|---|
| 0 | 見出し語または読みが、入力全体と完全に一致 |
| 1 | 見出し語または読みが、基準の語で始まる(ワイルドカードの場合は、見出し語または読みに一致) |
| 2 | 見出し語または読みに、基準の語が含まれる |
| 3 | それ以外 |

### 4.5 結果の再利用
文字を足しただけの入力では、前回の結果の中だけを調べ直します(`core::narrows`)。

- 条件: 辞書の選択が同じで、4つの欄のすべてで、新しい文字列が前の文字列で始まっている。
- ワイルドカード(`*`)を含むときは使わない(文字を足すと一致の範囲が広がることがあるため)。
- **`st.entries` を変更したときは、必ず `st.last_query = None` にすること**。前回の結果は添字で持っているため、語の並びが変わると無効になる(登録・編集・削除・読み直し・しおり表示の切替)。

### 4.6 強調表示
`Query::mark_terms` が、見出し語用・意味用・タグ用の語を返します。`core::mark_ranges` が、文字列の中の一致範囲を UTF-16 単位で返します(重なる範囲はまとめる)。

- ワイルドカードの語は、`*` で区切った断片ごとに強調する。英数字1文字だけの断片は、強調しない。
- 読みは、検索語と読みの両方をひらがなにそろえてから照合する。

## 5. 並び順

### 5.1 見出し語順(`core::sort_entries`)
読み込み直後と、登録・編集の後に、`st.entries` 全体をこの順に並べます。並べ替えのキーは次のとおりです。

| 見出し語の先頭 | キー |
|---|---|
| ASCII の英数字 | 見出し語(小文字)。読みがあっても使わない |
| それ以外 | 読みがあれば読み(`reading_norm`)、無ければ見出し語(小文字) |

- カタカナは、ひらがなと同じ扱いにして比べる。
- 文字コードの順で比べるので、数字 → 英字 → かな → 漢字 の順になる。
- キーが同じときは、見出し語(小文字)、辞書の添字、id の順で決める。

### 5.2 そのほかの並び順(`config::Sort`)
検索の結果(`st.matches`)に対して、安定ソートで並べ替えます。

| 値 | 内容 | 設定への保存 |
|---|---|---|
| `Word` | 並べ替えない(見出し語順、または検索の順位のまま) | する(`word`) |
| `UpdatedAsc` | 更新日時の昇順 | する(`updated_asc`) |
| `UpdatedDesc` | 更新日時の降順 | する(`updated_desc`) |
| `Bookmark` | しおりの追加日時の昇順 | しない |

しおり表示に入ると `Bookmark` に切り替え、出ると元の並び順に戻します。

## 6. 書き込みの安全手順

登録・編集・削除・取り込みは、すべて `safe::write(db, backup_root, f)` を通します。`f` の中の変更は、1つのトランザクションです。

| 手順 | 内容 | 失敗したとき |
|---|---|---|
| 1 | `BEGIN IMMEDIATE` で書き込みロックを取る(最大5秒待つ) | `Busy` |
| 2 | `PRAGMA quick_check` で、書き込み前の整合性を調べる | `CorruptBefore`(書き込まない) |
| 3 | 別の接続から、バックアップ API で `pre-write.db` へスナップショット。必要なら世代バックアップ | `Backup`(書き込まない) |
| 4 | `core::migrate` の後、`f` を実行してコミット | `Conflict` / `Sql`(ロールバックされる) |
| 5 | ファイルを開き直して `quick_check` | 壊れていたら `pre-write.db` から復元 → `RolledBack`。復元も失敗したら `RestoreFailed` |
| 6 | 成功後の状態を `latest.db` へスナップショット(失敗しても結果には影響させない) | — |

- 手順3 でロックを取った後にスナップショットを取るのは、ほかの人の変更をすべて含んだ状態を残すため。
- 復元(`safe::restore`)は、バックアップ自体を検査した後、同じフォルダに一時ファイルを作ってから置き換える。残っているジャーナルは消す。
- 復元に使うバックアップ(`safe::latest_backup`)は、検査に通るもののうち最も新しいもの。時刻が同じなら `latest` > `pre-write` > 世代 の順。

### 編集の衝突
`core::update` は、`WHERE id = ? AND updated_at = ?` で、読み込んだ時点の更新日時と一致するときだけ更新します。一致しなければ `Conflict` とし、上書きしません。同じ秒の中で続けて編集しても更新日時が変わるよう、新しい値は `max(現在, 以前 + 1)` にします。

### ほかの人の変更の検知
- 読み込み時に、辞書ごとのファイルの(更新時刻, サイズ)を控える(`safe::file_stamp`)。
- ウィンドウが前面に出たとき(`WM_ACTIVATE`)、控えと違っていれば読み直す。
- 書き込みの前に控えと違っていたら、書き込みの成功後に読み直す(メモリ上の内容が古いため)。

### 起動時の破損
読み込みで、破損を示すエラー(`SQLITE_CORRUPT` / `SQLITE_NOTADB`)が出た辞書は、復元するかを確認します。同じ辞書について確認するのは、1回の起動につき1度だけです。

## 7. 取り込みと書き出し

### 7.1 JSON(`json_io.rs`)
```json
{
  "format": "MyDictionary",
  "version": 1,
  "entries": [
    {
      "word": "一期一会",
      "reading": "いちごいちえ",
      "meaning": "一生に一度の出会い。\nその機会を大切にすべきだという教え。",
      "tags": ["四字熟語"],
      "links": ["公式サイト | https://example.com/", "[[温故知新]]"],
      "updated_at": 1730000000,
      "updated": "2024/10/27 12:33:20"
    }
  ]
}
```

**書き出し**: 項目の順番を保つため、文字列を手で組み立てています(エスケープだけ `serde_json` を使う)。辞書ファイルを読み直して、見出し語順で出力します。

**取り込み**:
| 項目 | 扱い |
|---|---|
| 全体 | 配列、または `entries` に配列を持つオブジェクト |
| `word`, `meaning` | 必須。無い項目は読み飛ばす |
| `tags` | 文字列の配列、または区切り文字入りの文字列 |
| `links` | 文字列の配列。無ければ `link`(文字列、改行区切り)を見る |
| `reading` | 任意 |
| `updated_at` | 正の整数なら、更新日時として使う。無ければ取り込んだ時刻 |
| `updated` など、そのほかの項目 | 無視する |

### 7.2 CSV / TSV(`import.rs`)
| 項目 | 内容 |
|---|---|
| 文字コード | UTF-8(BOM の有無どちらも)、UTF-16(BOM 付き)。どちらでもなければ Shift_JIS(CP932)として読む(`dialogs::decode_text`) |
| 区切り | 拡張子が `.tsv` `.tab` ならタブ、`.csv` ならカンマ。それ以外は、1行目にタブがあればタブ |
| 引用 | `"..."` で囲める。中の `""` は `"` 1つ。区切り文字と改行を含められる |
| 見出し行 | 1行目に、見出し語と意味の両方の列名があれば、列名で対応づける |
| 見出し行が無いとき | 左から 見出し語、意味、タグ、参照先、読み |
| 改行の表記 | 意味と参照先の中の `\n`(バックスラッシュと n)を、改行に変える |
| 空の行 | 読み飛ばす。見出し語か意味が空の行は、件数を数えて読み飛ばす |

列名(大文字小文字は区別しない):

| 列 | 名前 |
|---|---|
| 見出し語 | 見出し語、見出し、単語、語、word、term、headword |
| 意味 | 意味、説明、meaning、definition、description |
| タグ | タグ、tag、tags |
| 参照先 | 参照先、リンク、link、links、url |
| 読み | 読み、よみ、読み方、ふりがな、reading、yomi、kana |

### 7.3 登録(`import::insert_rows`)
見出し語と意味の組が、辞書の中またはファイルの中ですでに出ていれば、重複として読み飛ばします。`safe::write` の中で実行するので、全体が1つのトランザクションです。

### 7.4 JSON かどうかの判定
拡張子が `.json`、または内容(BOM と空白を除く)が `[` か `{` で始まっていれば、JSON として読みます。

### 7.5 サンプル
`sample/sample.tsv` と `sample/sample2.tsv` は、取り込める TSV の見本です(列名付き)。実行ファイルには含めていません。
自動テストでは、この2つのファイルが正しく解析でき、取り込めること、文中の `[[語]]` のリンク先が実在することを確かめています。

## 8. リンク

### 8.1 参照先の欄(`core::parse_links`)
1行に1つ。次の順に解釈します。

| 形 | 表示名 | 開く先 |
|---|---|---|
| `[[語]]` | 語 | `word:語` |
| `[表示名](開く先)` | 表示名 | 開く先 |
| `表示名 \| 開く先`(最初の `\|` で分ける。両側が空でないとき) | 表示名 | 開く先 |
| それ以外 | 行全体 | 行全体 |

### 8.2 意味の文中(`core::body_links`)
- `[[語]]`: 同じ行の中で閉じていて、中身が空でないものをリンクにする。表示では括弧を外す。
- `http://` `https://`: 空白、和文の括弧・句読点、`<` `>` `"` の手前までを URL とする。末尾の `. , ; : ! ? ) ] '` は含めない。

戻り値は、表示用の文字列と、リンクの範囲(UTF-16 単位)です。強調表示の位置は、表示用の文字列に対して計算します。

### 8.3 開く先の種類(`core::link_kind`)
| 種類 | 条件 | 動作 |
|---|---|---|
| `Word` | `word:` で始まる | アプリ内で移動する(検索欄をその語にし、完全に一致する語を選ぶ) |
| `Web` | `http://` `https://` で始まる | そのまま `ShellExecuteW` で開く |
| `Executable` | 拡張子が実行形式(下記) | 強い警告(既定は「いいえ」)の後に開く |
| `Other` | それ以外 | 確認の後に開く |

実行形式とみなす拡張子: `exe com bat cmd scr pif msi msp ps1 vbs vbe js jse wsf wsh hta lnk url reg jar cpl dll appref-ms`

`file:` 以外のスキーム(`mailto:` など。コロンの前が2文字以上)は、拡張子では判定せず `Other` とします。

### 8.4 クリックの判定
RichEdit の URL 自動検出(`EM_AUTOURLDETECT`)は使いません。URL の形をしていない表示名のリンク属性(`CFE_LINK`)を消してしまうためです。

- リンクの範囲と開く先を、`State::links` に持つ。
- `ENM_MOUSEEVENTS` を有効にし、`EN_MSGFILTER` でマウスの操作を受け取る。
- 左ボタンを離したとき、選択範囲が空なら(= ドラッグではなくクリックなら)、`EM_CHARFROMPOS` で文字位置を求め、`EM_POSFROMCHAR` で座標も確かめて、リンクの上かを判定する(`gui::link_at`)。
- 本文を書き換える処理を RichEdit のマウス処理の途中で行わないよう、`WM_APP_LINK` を自分に送ってから開く。
- リンクの上では、RichEdit をサブクラス化して `WM_SETCURSOR` を処理し、カーソルを指のマークにする。

`CFE_LINK` は、見た目(下線)のためだけに付けています。

## 9. 画面

### 9.1 寸法とフォント(96dpi 基準。`ui.rs`)
| 項目 | 値 |
|---|---|
| ボタン | 幅 108 × 高さ 36(`BTN_W`, `CTL_H`) |
| 1行の入力欄 | 高さ 36 |
| 候補リスト | 幅 320(固定)。1行の高さ 58 |
| ウィンドウ | 初期 1080 × 720、最小 960 × 520 |
| フォント | Yu Gothic UI。操作部品 10pt、補足 9pt、見出し 10pt 太字 |
| 本文(RichEdit) | 見出し語 20pt 太字、読み 11pt、補足 9pt、意味 12pt、参照先 10pt |

DPI が変わったとき(`WM_DPICHANGED`)は、フォントとリストの行の高さを作り直します。

### 9.2 部品
| 部品 | 実装 |
|---|---|
| ボタン | `BS_OWNERDRAW`。`ui::draw_button` が角丸で描く(Primary / Secondary / Danger / Toggle) |
| 入力欄 | 枠なしの `EDIT` を、親が描く角丸の枠の内側に置く(`ui::field`, `ui::paint_fields`)。フォーカス時は枠を青にする |
| 候補リスト | `SysListView32`(`LVS_OWNERDATA`、1列、見出しなし)。行は `NM_CUSTOMDRAW` で自前で描く(`gui::draw_row`)。行の高さは、空のイメージリストで確保する |
| 本文 | `RICHEDIT50W`(Msftedit.dll)。使えないときは `EDIT` で代用(`rich_ok`) |
| モーダル画面 | 専用のウィンドウクラスと、自前のメッセージループ(`dialogs::run_modal`) |

### 9.3 注意が必要な点
- **仮想リストの範囲選択**: Shift+クリックなどの範囲選択は、`LVN_ITEMCHANGED` ではなく `LVN_ODSTATECHANGED` で届く。両方を処理する。
- **Tab での移動**: 複数行の `EDIT` は、Tab での移動を親へ `WM_NEXTDLGCTL` で依頼する。通常のダイアログではないので、自分で処理する(`ui::next_dlg_ctl`)。
- **複数行の `EDIT` の Ctrl+A**: 標準では効かないので、メッセージループで補う(`ui::select_all_if_edit`)。
- **プログラムからの入力欄の変更**: `ui::set_text` は、`BUSY` カウンタを上げている間に設定する。`WM_COMMAND` の処理は、`BUSY` が上がっていれば通知を無視する(再入を避ける)。
- **状態の持ち方**: `State` は `GWLP_USERDATA` に置いた `Box` で、`gui::state` が `&mut` を返す。メッセージ処理は再入することがあるので、上の `BUSY` で、自分の操作が引き起こした通知を処理しないようにしている。

### 9.4 独自のメッセージ
| メッセージ | 用途 |
|---|---|
| `WM_APP_LOADED` | 読み込みスレッドからの結果(`Box<Loaded>`)。世代番号(`gen`)が合わなければ捨てる |
| `WM_APP_TRAY` | トレイのアイコンの操作 |
| `WM_APP_SHOW` | 二重起動したときに、既存のウィンドウを表示させる |
| `WM_APP_LINK` | 本文のリンクがクリックされた(`Box<String>`) |

### 9.5 起動と終了
- 二重起動は、名前付きミューテックス(`Local\MyDictionarySingleInstance`)で検出する。2つ目は、既存のウィンドウに `WM_APP_SHOW` を送って終了する。
- 閉じるボタンと Esc(入力が空のとき)は、`close_to_tray` が真ならウィンドウを隠し、偽なら終了する。
- トレイのアイコンは、設定にかかわらず常に表示する。

## 10. 設定ファイル

INI 形式です(`config.rs`)。`;` または `#` で始まる行はコメントです。

| セクション | キー | 値 | 既定 |
|---|---|---|---|
| `[general]` | `hotkey` | `Ctrl+Alt+D` の形。`none` で無効 | `Ctrl+Alt+D` |
| | `close_to_tray` | `true` / `false` | `false` |
| | `sort` | `word` / `updated_asc` / `updated_desc` | `word` |
| | `title` | ウィンドウのタイトルに表示する名前。書いたとおりに表示する。空ならアプリの名前 | 空 |
| | `shared` | `true` / `false`。共用フォルダでの運用 | `false` |
| `[dictionary.<ID>]` | `name` | 表示名。省略すると ID | — |
| | `path` | 辞書のパス。必須 | — |
| | `readonly` | `true` / `false` | `false` |

- ホットキーは、修飾キー(`Ctrl` `Alt` `Shift` `Win`)を1つ以上と、キー(英数字、`F1`〜`F24`、`Space`)1つ。
- パスの中の `%名前%` は、環境変数に置き換える。相対パスは、設定ファイルのあるフォルダが基準。
- 辞書が1つも無ければ、既定の辞書(`dictionary.db`)を使う。
- 解釈できない行は無視し、警告として画面の下段に出す(起動は止めない)。
- 廃止したキー `timing_log` は、警告を出さずに無視する。
- 設定画面で保存すると、ファイル全体を書き直す(`config::to_ini`)。コメントは残らない。設定ファイルと同じフォルダの辞書は、ファイル名だけで書く。

### 共用フォルダでの運用(`shared = true`)
設定ファイルを複数人で使うことを示すフラグです。設定ファイルの場所(実行ファイルの隣か、`%AppData%` か)とは独立しています。

| 項目 | 動作 |
|---|---|
| しおり | 読み込まない・保存しない。ボタンと右クリックの項目を出さない。Ctrl+D は案内だけ出す |
| 並び順 | 変えても設定ファイルに書かない |
| 設定の保存 | 確認を出してから書く |
| タイトル | 変えない(`title` の値だけで決まる。`config::window_title`) |

フラグを切り替えたとき(設定の保存、設定ファイルの再読み込み)は、しおりを読み直し、部品の表示とレイアウトを更新します(`gui::apply_mode`)。

設定画面のホットキーの欄(`msctls_hotkey32`)は、Win キーを扱えません。欄を変更しなかった場合は、元の値(Win キーを含む)をそのまま残します。

### 画面の確認
画面は自動テストの対象外です。確認の項目と結果は、[テストチェックシート](test-checklist.md) にまとめています。

開発時は、Linux 上で Wine と仮想ディスプレイ(Xvfb)を使い、実行ファイルを起動して画面を撮影・操作して確認しました。Wine に日本語フォントが無い場合は、レジストリの `FontSubstitutes` で `Yu Gothic UI` などを手元のフォントに割り当てる必要があります。

### 版を上げてリリースする
1. 次の3か所の版をそろえて変える。
   - `Cargo.toml` の `version`
   - `app.rc` の `FILEVERSION` / `PRODUCTVERSION` と、`FileVersion` / `ProductVersion`
   - `src/ui.rs` の `APP_VERSION`
2. `docs/release-notes.md` を、その版の内容に書き換える。
3. 既定のブランチに反映する。
4. GitHub の Actions の画面で「release」→「Run workflow」を選び、`tag` に `v2.00` のようなタグ名を入れて実行する
   (`v2.00` のようなタグを push しても、同じ処理が動く)。

GitHub Actions(`.github/workflows/release.yml`)が Windows 上でテストとビルドを行い、タグと Release を作って `MyDictionary.exe` を添付します。
`tag` を空にして実行すると、Release は作らず、ビルドした exe を Artifacts に残すだけです(Windows でのビルド確認に使えます)。
同じタグの Release を作り直したいときは、`replace` にチェックを入れて実行します(古い Release とタグを削除してから作成します)。

## 性能

開発用の Linux 環境で、10万語のテスト用データを計測した値です(Windows の実機での値ではありません)。

| 処理 | 時間 |
|---|---|
| 起動時の読み込み(開く + 全件を読む + 並べ替え) | 約 140〜160 ms |
| 検索1回(全件を調べる場合) | 約 1〜20 ms |
| 検索1回(文字を足しただけの場合) | 前回の結果の件数に比例して短くなる |

- 読み込みは別スレッドで行うので、その間もウィンドウは表示され、入力できる。読み込み中に入力した語は、読み込みが終わった時点で反映される。
- 2万件以上のときは、検索用の文字列の準備を最大4スレッドで行う。
- 書き込みは、検査とバックアップを伴うので、辞書の大きさに比例して時間がかかる。

## 13. 既知の制約

| 項目 | 内容 |
|---|---|
| 共有フォルダ | SQLite の性質上、同時書き込みによる破損を完全には防げない。安全手順は、破損の検出と復元のためのもの |
| バックアップ | その PC から書き込んだときだけ作られる。復元の瞬間にほかの人が書き込んでいる場合の競合は防げない |
| 読み | 自動では付かない。ローマ字の入力は、かなの読みに一致しない |
| 五十音順 | 文字コードに基づく簡易なもの。長音や小さい字の扱いは、国語辞典と一致しない。読みの無い漢字の語は、最後にまとまる |
| かなの区別 | ひらがなとカタカナを区別しないのは、読みだけ。見出し語・意味・タグは表記どおり |
| ホットキー | 設定画面では Win キーを指定できない(設定ファイルでは可能) |
| しおり | 書き出しに含まれない。辞書のパスを変えると、付けたしおりは表示されなくなる |
| 表示 | ダークモードには対応していない |
| 画像 | 図や画像は埋め込めない(参照先として、ファイルや URL を登録する) |
| 署名 | 実行ファイルに署名が無い。Smart App Control が有効な PC では、起動やビルドがブロックされることがある |
| 状態の扱い | メッセージ処理の再入を `BUSY` カウンタで避けている。新しい通知を処理に加えるときは、自分の操作が引き起こす通知を無視できているかを確認すること |
